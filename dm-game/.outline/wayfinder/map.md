# Wayfinder Map: DM 답장 카드 게임

## Destination

공개 URL로 배포된 2인 온라인 웹 게임.

- 두 플레이어가 각자 기기(모바일 우선)로 같은 방에 접속한다.
- 한 라운드: 보내는 사람(A)이 손패에서 **정상 DM 카드**를 골라 보낸다 → 받는 사람(B)이 손패에서 **이상한 답장 카드**를 골라 보낸다 → 두 카드가 모바일 메시지 대화 화면처럼 공개된다.
- 점수·승패 없음. 라운드마다 A/B 역할을 교대한다.
- 카드 텍스트는 **관리자가 별도 편집 화면에서 미리 덱으로 구성**한다 (정상 DM 카드 / 답장 카드 두 종류). 플레이어는 그 덱으로 플레이한다.

완료 판정: 서로 다른 두 기기에서 공개 URL로 방을 만들고 입장해, 관리자가 입력한 덱으로 역할을 교대하며 여러 라운드를 끝까지 진행할 수 있다.

## Notes

- 참고 영상: https://youtube.com/shorts/5DEbN1eirRM ("미치도록 빵터지는 보드게임 답장 모음집", 짭쌀떡). 영상 내용은 아직 직접 확인하지 못했다. 제목만 확인했다.
- 원작 보드게임의 이름·아트·카드 문구를 그대로 재현하지 않는다. 메커니즘만 참고하는 오리지널 게임이다.
- DM 화면은 특정 메신저 앱의 상표나 외형을 그대로 베끼지 않는 범용 모바일 메시지 스타일로 만든다.
- 코드와 지도는 `evalHelperBSQ` 레포의 `dm-game/` 하위 폴더에 둔다.
- 용어:
  - **DM 카드**: 정상적인 내용의 메시지 카드. 보내는 사람이 고른다.
  - **답장 카드**: 대화를 이상하게 만드는 답장 카드. 받는 사람이 고른다.
  - **덱**: 관리자가 구성한 DM 카드와 답장 카드 묶음.
  - **방**: 두 플레이어가 함께 플레이하는 세션.

## Decisions so far

- 호스팅: 개인 쿠버네티스에 Istio Gateway·VirtualService로 공개하고 수동 배포한다. → [호스팅·실시간 통신 플랫폼 선택](tickets/hosting-realtime.md)
- 저장소·상태: 덱은 PVC 위 SQLite에, 방 상태는 메모리에만 두고 replica는 1개(Recreate)로 고정한다. → [서버 상태·덱 저장소 구성](tickets/server-state-storage.md)
- 관리자: 공유 비밀번호 1개(Secret 주입, 세션 쿠키)로 보호한다. 카드는 한 장씩 입력, 여러 줄 붙여넣기, JSON/CSV 가져오기·내보내기로 관리한다. → [관리자 편집 화면 접근 보호](tickets/admin-access.md)
- 스택: Go 서버와 React + Vite + TS 프론트엔드. 프론트엔드는 Go embed로 넣어 컨테이너 하나로 서빙한다. → [프론트엔드·서버 기술 스택](tickets/tech-stack.md)
- 방: 방 코드와 초대 링크로 입장한다. 닉네임을 입력하고 방장이 선공한다. 연결이 끊기면 토큰으로 5분 안에 재접속할 수 있다. → [방 생성·입장 흐름](tickets/room-flow.md)
- 카드: 텍스트만 넣고 DM 카드와 답장 카드를 자유롭게 조합한다. 한 라운드는 DM 1장과 답장 1장이다. 이름이 있는 덱을 여러 개 두고 방장이 고른다. CSV 컬럼은 `deck,kind,text`. → [카드·덱 데이터 모델](tickets/card-model.md)
- 라운드: 손패는 종류별 5장을 유지하고, 시간 제한은 없다. 방장이 5/10/20 라운드 중에서 고르고, 플레이 중에는 현재 라운드만 보이며 끝나면 전체 대화를 모아 본다. → [라운드 세부 규칙](tickets/round-rules.md)

## Not yet specified

- 기본 덱 콘텐츠: 초기 카드 문구를 누가, 몇 장이나 작성하는가.
- 결과 공유: 웃긴 대화를 이미지로 저장하거나 공유하는 기능이 필요한가.
- 부적절한 콘텐츠: 공개 URL에서 생길 수 있는 남용을 어떻게 다루는가.
- 관전자나 화면 공유 모드가 필요한가.
- 다국어 지원.
- 배포 산출물: 컨테이너 이미지 레지스트리, 매니페스트 형태(raw YAML, Helm, Kustomize), 도메인과 TLS 인증서 처리.
